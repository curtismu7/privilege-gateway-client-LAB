# Safety

- Loopback bind only (`PGC_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it).
- The Host header must be a loopback name (or one in `LAB_ALLOWED_HOSTS`); writes must be same-origin (`Origin` and `Sec-Fetch-Site` checked). Tests send a foreign Host and cross-origin POSTs.
- The one port is 7833; any other, or a reserved one, is refused at start.
- An unreadable body or an unknown API route answers JSON (`{error, message}`), never an HTML error page.
- The shelf route reads only `SHELF_URL` from the app's environment: the vendored helper's fallback to a settings file outside this repo is switched off by passing it only that key.
- Settings come only from this lab's own `.env` beside the compose file. Agent keys are write-only: never returned, logged or traced. No tenant, client id or real hostname ships; hosts are `.invalid` / `.example`.
- Netguard (`server/src/netguard.js`, self-test run by the doctor and `/api/health`): in Mock the only reachable origin is the in-process mock gateway (`https://mock-gateway.invalid`, no socket); in Real exactly one origin, the gateway named in this lab's own `.env`, https (plain http only to loopback), no link-local or metadata literals. The shared gateway-real client makes its own fetch and never follows a redirect; the lab calls `assertAllowed(url)` before every Real call. A test spies on `fetch` and on socket connects and asserts zero non-loopback attempts across every Mock door, tool and scenario.
- Keys: a Real agent key is scrubbed from every captured exchange, error and message at capture, shown only as its length, and never returned, logged or traced. A test greps every response and log line of a run against a gateway that echoes the key back.
- Bounded input: JSON bodies 16 KB, tool arguments 8 KB and 8 levels deep (checked iteratively), door and tool names by pattern, and a door must be in the active door list. A Real door without its own key is a 409: another door's key is never sent to it.
- Mock sign-in (rule 11): the persona routes are mounted only when `IDP=mock` AND `ALLOW_MOCK_SIGNIN=1`. Each request is then refused (403 with a stable reason) behind a proxy header (unless the Host is a `LAB_ALLOWED_HOSTS` name, which is how the shared lab-proxy reaches a lab), on a non-loopback bind (Docker is allowed only with the loopback publish marker `LAB_PUBLISH=loopback` that compose sets next to its `127.0.0.1:` publish), from a non-local connection, for a foreign Host, and in Real. `NODE_ENV` is not a guard: the image sets it. The doctor fails if the setting is on and the listener is not loopback. `demoAdmin` exists only while `<PGC_DATA_DIR>/ALLOW_ADMIN_PERSONA` exists.
- Sessions: an HMAC-signed `HttpOnly; SameSite=Strict` cookie per workspace holding a persona id or four claims, never a token. A tampered, expired, foreign-workspace or other-secret cookie signs nobody in.
- Real page login (rule 16, `server/src/auth/pingoneLogin.js`): pi.flow only. It sends nothing until Real is on and the lab's own `.env` names the PingOne environment and client; every request goes through the netguard's `assertLoginAllowed` (https, exactly the configured environment's origin and path, no credentials in the URL) and the module's own check, never follows a redirect, has a timeout and a 256 KB reply cap, and answers a named JSON error. The password is typed in the dialog, posted once, never stored, logged, traced or returned; the flow id, PingOne cookies, authorization code and access token never leave the server. It drives a password only: an MFA or consent step ends the run with the status named. Tested against stubbed PingOne responses only. UNVERIFIED: the token and userinfo steps against a live tenant, and a tenant policy beyond a password.
- Workspaces: ids are 1 to 32 lowercase letters, digits and dashes (a bad `X-Workspace` is a 400, never the default); at most 20; the trace sink file is mode 600, capped at 1 MB, and holds only already-redacted hops.
- customer.config is plain text only (no `<`, `>`, `@`, `://`, `{{`, control or bidi characters), size-capped, and a rejected value is never echoed back.
