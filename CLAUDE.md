# privilege-gateway-client-LAB

Demo-tier standalone app: a client for a PingOne Privilege MCP gateway. Pick one of three doors (`lab-banking-full`, `lab-banking-limited`, `lab-banking-blocked`), discover tools, run one, see the verdict first, then the evidence (movie reel, decoded tokens, shared sequence view). Port 7833. Env prefix `PGC_`. Spec: the owner-approved build plan (2026-11-21); the design mock is a visual spec only, never code to copy.

- Status: server side done (steps 1b, 1c): in-process mock gateway, netguard, doors, hops, verdict model, mode/info/reset routes, Real via the shared gateway-real hop; stories + 3 vertical packs, customer.config, workspaces, guarded Mock personas, Real pi.flow page login (stub-tested only), talk track, presenter flag. Web (step 2a): the shell, the verdict-first stage, identity rail with the three doors, the four tabs (Tools, Arguments and response, Evidence, simulated Agent chat) on the server API. Step 2b: the Panels dock and four FloatingDialog panels (Movie reel, Token sequence, Sequence, Gateway trace) in `web/src/panels/`, all driven by ONE walkthrough over the run's hop array (`stepper.js` is this lab's tested copy of the shared walkthrough reducer; `useRunStepper.js` plans where Simulate stops; `tokenFlow.js` compares tokens). A panel body is a function of its props only (a popped-out panel is a separate React root). Step 2c (Demo tier): stories (`StoryPanel.jsx`, `storyView.js`; `?story=S0n` links and a picker, `useLab.runSpec` runs a story's or step's run), the vertical packs through the TopMenu `vertical` control and `?vertical=` on `/api/stories` and `/api/talk-track`, `useContent.js` (config, stories, talk track from the server), `ModeStatus.jsx` (rule 26: the source at all times and the Real-asked-but-unavailable alert), `signinView.js` (why sign-in is unavailable), presenter mode and the Reset of the page in `App.jsx`, `TalkTrack.jsx` (non-modal; see below), branding and the workspace id (`api.js`).
- Run: `./scripts/run.sh` (http://localhost:7833; `PORT=7933 npm start` and `PORT=7933 npm run doctor` for another port). Test: `npm test` (server `node --test test/*.test.js`, a glob; web vitest; `scripts/*.test.mjs`). Preflight: `npm run doctor`. Content pack: `npm run content-pack`. Build: `npm run build`.
- Layout: `server/src/` (`config.js` identity and port, `doors.js` door and tool config, `mockGateway.js`, `mockClient.js`, `netguard.js`, `mode.js`, `realDoor.js`, `verdict.js`, `hops.js`, `lab.js` core, `safety.js`, `settings.js`, `checks.js` doctor checks, `app.js` routes, `index.js`, `cast.js` + `stories.js` + `data/` (stories and the 3 vertical packs), `customer.js`, `workspaces.js`, `talkTrack.js`, `auth/` (personas, guards, session, pingoneLogin); vendored: health, doctor, trace, shelfLink, gatewayTrace, gatewayReal, `vendor/` hop-detail), `web/src/panels/` (PanelDock, ReelPanel, TokensPanel, SequencePanel, TracePanel, StepperBar, RunNote, stepper, useRunStepper, tokenFlow; lab code, never inside a vendored folder), `e2e/panels.py` and `e2e/diagram.py` (browser proofs, not in `npm test`), `web/src/` (vendored top-menu, components/JsonPane etc., floating-dialog, evidence, gateway-trace; lab-owned: App, VerdictCard, IdentityRail, ToolsTab, ArgsTab, EvidenceTab, ChatTab, SignIn, `useLab.js` (the one data hook), `verdictView.js` and `agent.js` (pure), `json/JsonPane.jsx` shim; vendored: signin-dialog too; `testLab.js` runs the real server lab inside the web tests), `docs/`.
- Rules that bite:
  - **Vendored files are byte-for-byte from AI-DEMO-Standalone `origin/main`** (after `git fetch`; never a sibling lab, never the working tree), each with a pin file and a pin test. Never hand-edit one: change the canonical first, `cp`, re-pin. The canonical `top-menu.sha256` is stale: regenerate it. Copy every file of a shared folder (TopMenu needs `ReleaseNotes.jsx`).
  - Stories and the talk track (`docs/talk-track.md`) use `{{castX}}` tokens; every vertical pack must define every token (a test and the doctor fail otherwise). A story names the run it teaches and a test replays it: change a verdict and the story fails.
  - Mock sign-in needs `IDP=mock` AND `ALLOW_MOCK_SIGNIN=1` and is refused behind a proxy, on a non-loopback bind and in Real. The Real page login is pi.flow on the local lab: no token, flow id, cookie, code or password ever leaves the server. The hosted lab (`PGC_HOSTED=1` only) uses the redirect sign-in instead (owner exception to rule 16, 2026-11-23): PingOne sends the authorization code through the browser to `/callback`, which only the browser that started the sign-in can finish; the code is exchanged on the server with PKCE and tokens still never leave it. Do not turn either into the other. It is tested against stubs; never point a test at a real PingOne.
  - Loopback bind, Host check, same-origin writes; Docker publishes `127.0.0.1:` only; the image sets `PGC_BIND`. Default port 7833 (claimed for this lab); `PORT` overrides it.
  - Settings only from this lab's own `.env` beside the compose file. Never `~/Documents`, never `~/Development/.env`, never another project's vault. `.env.example` lists names only. Agent keys are write-only: never returned, logged or traced.
  - Only `.invalid` / `.example` hosts and neutral names in shipped text. Door names `lab-banking-full` / `lab-banking-limited` / `lab-banking-blocked` and users `aidemo`, `demouser`, `demoAdmin` are approved (all three are ordinary users: no admin flag, no switch file, owner 2026-11-22). No tenant ids, client ids or real hostnames.
  - Panels: inside `.pgc-fd` the shared accent tokens are ink and `--danger-text` is amber (app.css), so nothing in a panel is red unless the run is a Real upstream failure (`.pgc-fd--red`); a refusal gets a lock (`.pgc-fd--refusal`). No second stepper: the shared reel/sequence walkers only call the one `onSelect`. A new panel goes through `PANELS` in `PanelDock.jsx`.
  - Colour: red is only the Sign in button, the thin header rule and a real error. Refusals are amber with a lock and the words; selected tabs, tools and doors use ink or a focus-blue edge (app.css), never the shared red fill.
  - Real mode may only say `observed` (read from the response) or `inferred`; `checked` is for the lab's own simulated gateway. Refusals are never red. A verdict always carries a word.
  - Hop verdicts (demo-hop/1): `deny` only when a policy refused (401, 403, a refused tool); a hop that could not complete (no answer, 5xx, any other failed status, a JSON-RPC error, a backend that did not answer) is `error`, which the shared reel words "failed". `app.css` colours `error` with `--danger-text` (amber, red only in a Real upstream failure) and gives it no lock. Hops use the shared catalog kinds (door-picked, discover, tool-call, policy-check, verdict); there is no fallback table.
  - Diagrams (rule 5 and 17, owner 2026-11-22): the lab has ONE drawn diagram, the Diagram panel: a ReactFlow call-path box diagram from `diagrams/pgc-call-path.json` (diagram-studio/1), loaded by name (`web/src/diagrams/loadDiagram.js`, own validator `diagramSchema.js`), drawn by `panels/CallPathDiagram.jsx` through the vendored `diagram-kit` (never edited). No node or arrow is built by hand in JSX (a test fails on one), no mermaid, no UML look. `steps[].hop` in the data names a hop kind (or `kind:verdict`), so the hop the one walkthrough is on lights its arrow. The sequence view stays the shared evidence `SequenceView` with `MovieReel` and `StepDetailPanel`. The Diagram panel has no pop-out (React Flow cannot measure boxes in another window); its moved boxes live in `PanelDock` (a closed panel's body is unmounted). Every JSON and token view goes through the vendored JsonPane (no hand-rolled `atob`).
  - `node --test test/*.test.js` with a glob. No EC key generation with `crypto.generateKeyPair` (sync or async; it crashed Node 20 CI): use `createECDH` + `createPrivateKey`. Node 26 only.
  - No AI attribution anywhere (no co-author trailer, no "Generated with" line) in commits, files or docs.

- **Real agent chat (2026-11-22, spec `docs/specs/2026-11-22-real-agent-chat.md`):** `server/src/agentChat.js` is a Messages API tool loop (owner chose lab-hosted over Managed Agents; model `claude-sonnet-5-5`, effort low, `fallbacks: "default"`). It discovers the door and runs every tool through `lab.discover` / `lab.call`, so verdicts, hops and keys stay as for a Tools-tab run. `POST /api/agent`; `PGC_ANTHROPIC_API_KEY` (write-only) and `PGC_AGENT_MODEL`. Netguard `decideModel`: Real only, one origin: `https://api.anthropic.com`, or the Privilege LLM gateway `PGC_LLM_GATEWAY_URL` names (that wins; it calls `<gateway>/llm/anthropic` with the llm-scoped `PGC_LLM_VIRTUAL_KEY` as a bearer, without effort or the fallback beta). **Hosted (`PGC_HOSTED=1`, `docs/hosted.md`):** Real calls need a Real page login, through the redirect sign-in (`/api/auth/redirect/start` → PingOne → `/callback`; owner exception to rule 16, one login across hosted demos; the local lab keeps pi.flow); one workspace per browser (cookie, LRU-evicted at the cap); the mode is fixed (409); Reset clears only the caller's workspace; pending sign-ins are capped and expire; a daily agent cap per person counts only turns that reached the model. Build the SDK client lazily (it throws in jsdom). The shared Real client keeps only tool name and description, so the Real tool schema is read from the captured `tools/list` reply (`schemasFromWire` in `lab.js`); `server/src/toolSchema.js` turns it into the form and the model's tool definitions. Mock keeps the simulated agent and the Mock samples. The agent also gets the lab's `call_unlisted_tool` (for a tool the user names that the gateway did not list; the gateway decides, which is how a refusal shows in the chat). Stories in Real discover first and use the listed arguments (`runSpec`).
